# 0001 · 插件级启停交宿主, 指令前缀内部化

## 状态

已采纳 (2026-10-18)

## 背景与问题

本项目最初的全局配置里有 `enabled` (插件级启用开关) 与 `commandPrefix` (用户可改的指令前缀), 带来两个问题:

1. `enabled` 与宿主状态重复: NapCat 自身就能启用/停用插件 (`pluginManager.setPluginStatus`), 停用后宿主不再调用 `plugin_onmessage`。插件内再放一个 `enabled` 就有了两个真相源——用户在插件配置里关掉, 宿主侧却可能仍显示"已启用", 反之亦然。
2. `commandPrefix` 允许用户修改, 但帮助产物是**构建期离线生成**的静态图片/文本, 前缀写死其中; 改前缀不会同步帮助, 造成帮助与实际行为不一致。

## 被放弃的方案与理由

- **保留 `enabled` 但隐藏 / 只读**: 它仍是配置字段, 仍会接受外部输入并经清洗, 没有消除"两个真相源"。
- **保留 `commandPrefix` 可配置, 并运行时动态生成帮助**: 帮助生成是离线流程 (外部渲染成图片), 运行时动态化成本高、收益低; 前缀对本插件本就无需用户调节。
- **把前缀硬编码在各引用点而非单一常量**: 会重新引入多处漂移 (消息解析、帮助生成、文档)。

## 结论

- 插件级全局启停**完全交宿主**; 配置文件不含 `enabled`, 插件不在消息入口自建全局门禁。
- 指令前缀固定为**插件内部常量** `COMMAND_PREFIX` (取值 `#steam`, 定义于 `packages/shared/src/config.ts`), 消息解析、帮助生成、WebUI 等所有引用点指向它, 不再暴露给用户修改。
- 会话级启停由配置之下的 `session-config.json` 承载 (见 [0002](./0002-group-only-and-session-config.md)), 与插件级启停不冲突。
- 由此确立一般原则: **配置项只承载需要用户调节的值**; 作者定死、用户无需改的值应是常量。
